# Генератор ссылок Qlik

## Когда использовать

Используй этот skill только если пользователь явно просит:

- собрать ссылку на `Qlik`, `Qlik Sense` или `Клик`
- создать ссылку на `Qlik`, `Qlik Sense` или `Клик`
- сделать ссылку на `Qlik`, `Qlik Sense` или `Клик`
- `сделай ссылку` на `Qlik`, `Qlik Sense` или `Клик`
- `сделай ссылку в клик`
- `сделай ссылку в qlik`
- `создай ссылку в клик`
- `сформируй ссылку qlik`
- сформировать ссылку с фильтрами и прямо упоминает `Qlik`, `Qlik Sense` или `Клик`
- дать ссылку на конкретный лист и прямо упоминает `Qlik`, `Qlik Sense` или `Клик`

Упоминание `Qlik`, `Qlik Sense` или `Клик` в запросе обязательно.
Если в текущем сообщении пользователя нет слов `Qlik`, `Qlik Sense`, `Клик`, `в клик`, `в qlik`, skill не должен запускаться, даже если по контексту уже понятно, о каком листе идёт речь.

Не используй этот skill, если пользователь:

- задаёт общий вопрос по `Qlik`
- просит найти поле, меру, переменную или источник данных
- просит написать `SQL`
- обсуждает структуру приложения, но не просит собрать ссылку

## Обязательные правила

- Работай только с фиксированным списком разрешённых приложений.
- Всегда нужен конкретный лист, ссылка без листа не считается готовым результатом.
- Для построения ссылки используй `AppID` и `SheetID`, а не только названия.
- Названия приложений и листов показывай пользователю в читаемом виде, но внутренне опирайся на идентификаторы.
- Если для одного названия листа есть несколько `SheetID` или для одного `SheetID` есть несколько названий, не делай выбор автоматически: попроси пользователя уточнить.
- На первом шаге никогда не предлагай `technicalSheets`.
- По умолчанию предлагай пользователю только `mainSheets`.
- Нетехнический лист считай вариантом по умолчанию.
- `technicalSheets` предлагай только если пользователь явно просит технический лист или если нужный лист не найден в основном списке.
- Русские названия полей и значений поддерживаются обязательно.

## Источник данных

Используй сохранённый реестр приложений и листов `qlik_link_registry.json`.

Список полей для фильтров храни отдельно в `qlik_filter_fields_registry.json`.

Правила формата значений полей храни отдельно в `qlik_field_value_rules.json`.

Реестр содержит:

- разрешённые `AppName`
- соответствующие `AppID`
- список листов `SheetTitle` + `SheetID`
- список `mainSheets` для выбора по умолчанию
- список `technicalSheets` для технических листов
- секцию `ambiguities` с неоднозначностями по листам

Техническим считай лист, если в `SheetTitle` есть `dev`, `test` или `тест` в любом месте без учёта регистра, либо если в названии есть номер в круглых скобках, например `(1)` или `(2)`. Остальные листы считай основными.

## Поля для фильтров

Пока список полей для фильтров формируй только из модели данных приложения.

Список полей формируй на уровне всего приложения, а не на уровне конкретного листа. Один и тот же набор полей считаем доступным для всех листов приложения.

Поля не показывай пользователю сразу сплошным списком, если он сам этого явно не просит.

По умолчанию не веди пользователя через группы полей.

Сначала проси пользователя написать своими словами, по каким полям нужен фильтр.

Правила на текущем этапе:

- источник полей: основной `qvs` приложения и подключённые `qvs`-скрипты из потока модели данных
- основной путь к `qvs`: `//eksmo-office/co/SERVICES_IT/QLIK/QlikShare/QProject/SourceDocuments/QData/DataTier1/QlikScripts/qvs_copy`
- формат значений поля сначала смотри в `qlik_field_value_rules.json`
- `qlik.vw_AppSheetObjectsCurrent` для списка полей пока не использовать
- на типы визуальных элементов и filter pane пока не ориентироваться
- когда в `qlik.vw_AppSheetObjectsCurrent.ObjectType` появятся полезные значения, можно будет добавить второй источник

Папка `//eksmo-office/co/SERVICES_IT/QLIK/QlikShare/QProject/SourceDocuments/QData/DataTier1/QlikScripts/qvs_copy` является строго read-only источником для этого skill.

Запрещено:

- редактировать файлы в этой папке
- сохранять в эту папку новые файлы
- удалять файлы из этой папки
- переименовывать файлы в этой папке

Разрешено только чтение `qvs` из этой папки для формирования и обновления внутренних реестров skill.

Техническими пока считай поля, названные только на английском, а также поля с префиксами `_` и `%`.

Поля с `GUID` не исключай автоматически, если они выглядят как пользовательские поля модели данных.

Если поле уже существует в `qlik_filter_fields_registry.json` для выбранного приложения, не считай его отсутствующим только потому, что его не было в сокращённом списке вариантов или в твоей предварительной подсказке.

В таком случае:

- сначала проверь точное совпадение по реестру полей приложения
- если точное совпадение найдено, принимай поле как валидное поле приложения
- если нужно, предлагай его как подтверждённый вариант пользователю

Если пользователь не указал поля совсем, спроси текстом, по каким полям и значениям нужен фильтр.

После того как пользователь написал поля, сначала сопоставь их с реестром и ответь коротким подтверждением в духе:

- `Правильно понимаю, нужны поля: ... ?`
- `Если всё верно, сформирую ссылку.`

Если пользователь в следующем сообщении меняет поле, заменяет одно поле другим, убирает фильтр или добавляет новый фильтр, считай набор фильтров изменённым и заново проверь все изменённые поля по реестру приложения.

После любой такой правки снова коротко подтверди итоговый набор распознанных полей, прежде чем формировать ссылку.

Группы полей можно использовать только как запасной сценарий, если пользователь сам просит помочь подобрать поля или если по тексту не удалось уверенно понять, какие поля имелись в виду.

Для `Факт продаж` поле `Автор произведения` считай валидным полем группы автора / редакции.

Метрики и числовые показатели вроде `руб.`, `шт.`, `количество`, `выручка`, `клики`, `добавления в корзину` не показывай на первом шаге выбора поля, если пользователь сам явно не просит такие поля.

Если нужно пересобрать список полей, читай `qvs` именно из папки `//eksmo-office/co/SERVICES_IT/QLIK/QlikShare/QProject/SourceDocuments/QData/DataTier1/QlikScripts/qvs_copy`, а не из локальной копии внутри проекта.

Если в основном `qvs` приложения есть подключения через `Must_Include` или `Include` к другим `qvs`-файлам модели данных, учитывай и эти подключённые `qvs` при сборке списка полей.

Это особенно важно для случаев, когда поля вынесены в отдельные `qvs`-скрипты со справочниками.

`qvs` из папок `меры` и `измерения` для списка полей модели данных не используй, так как это не основной источник полей фактической модели данных.

Если пользователь указал поле, которого нет в списке полей приложения, не отбрасывай его молча.

В этом случае:

- сначала предложи пользователю похожие найденные поля, если они есть
- отдельно предложи вариант подтверждения: `такое поле точно существует, отфильтруй по нему`
- если пользователь явно подтверждает, что поле существует, разрешай собрать ссылку с этим полем как с пользовательским override

- `Факт продаж`
- `Дашборд Редакций`

- `Маркетинговый дашборд`

## Входные данные

Для готовой ссылки нужны:

1. приложение
2. конкретный лист
3. фильтры

Если чего-то не хватает, сначала уточни недостающие данные.

Слова `лист` и `отчёт` считай равнозначными в пользовательском запросе.

Если приложение не указано явно, первым сообщением предложи выбрать одно приложение из разрешённого списка. Не проси пользователя самому вспоминать варианты, а сразу покажи доступные приложения.

Если доступен инструмент интерактивных вопросов, для выбора приложения используй именно его, чтобы пользователь мог нажать на вариант из списка, а не вводить название руками.

Если пользователь указал только название листа или отчёта без приложения, сначала попробуй найти такой лист по всем разрешённым приложениям.

Правила:

- если такой лист или отчёт найден только в одном приложении, спроси: `Вы имеете в виду лист "<Лист>" в приложении "<Приложение>"?`
- если найдено только одно подходящее приложение, не пиши `Выбери приложение` и не показывай интерактивный выбор приложения
- если такой лист или отчёт найден в нескольких приложениях, предложи выбрать только из списка этих приложений
- после подтверждения или интерактивного выбора приложения не спрашивай повторно тот же самый лист или отчёт, который уже был указан пользователем; сразу найди его внутри выбранного приложения и продолжай работу
- если в выбранном приложении найден ровно один подходящий лист по уже указанному названию, используй его сразу без дополнительного вопроса
- только если внутри уже выбранного приложения по указанному названию осталось несколько листов, попроси выбрать лист интерактивно
- если лист или отчёт не найден, сообщи об этом и предложи выбрать приложение вручную

Если фильтры нужны, но пользователь ещё не указал поля, сначала попроси его написать поля и значения в свободной форме.

## Форматы фильтров

Поддерживай следующие типы фильтров:

- одно значение
- список значений

Сначала приведи ввод пользователя к нормализованной внутренней структуре, потом собирай ссылку.

Примеры нормализованного смысла:

- `Издательство = Эксмо`
- `Канал = [WB, Ozon, ЧГ]`
- `Месяц = [Январь, Февраль, Март]`
- `Год = [2024, 2025, 2026]`

Подтверждённый синтаксис фильтров в URL:

- одно значение: `/select/Год/2021`
- список значений одного поля: `/select/РДЦ/РДЦ Екатеринбург;РДЦ Новосибирск`
- список месяцев: `/select/Месяц/Январь;Февраль;Март`
- список лет: `/select/Год/2024;2025;2026`
- несколько полей: добавляй несколько блоков `/select/{Поле}/{Значения}` подряд

Диапазоны пока не поддерживай. Если пользователь просит диапазон, предложи вместо этого список конкретных месяцев, лет или значений.

## Шаблон ссылки

Подтверждённый шаблон ссылки на конкретный лист без очистки фильтров:

`https://co-qlik/sense/app/{AppID}/sheet/{SheetID}/state/analysis`

Используй этот вариант только если пользователь явно просит не очищать фильтры или сохранить текущее состояние.

Подтверждённый шаблон ссылки с фильтрами без очистки:

`{base}/sense/app/{AppID}/sheet/{SheetID}/state/analysis/select/{Field1}/{ValueOrValueList1}/select/{Field2}/{ValueOrValueList2}`

Значения одного поля разделяй через `;`.

Если пользователь передал ссылку или пример с другим протоколом, сохраняй тот же `http` или `https`. Если пользователь не уточнил протокол, по умолчанию используй `https://co-qlik`.

## ClearSelections

Это поведение по умолчанию.

Если пользователь просит открыть лист:

- убери из ссылки `/state/analysis`
- добавь `/options/clearselections`
- после этого, если нужны фильтры, добавляй блоки `/select/...`

Подтверждённый шаблон:

`{base}/sense/app/{AppID}/sheet/{SheetID}/options/clearselections/select/{Field}/{Value}`

Если пользователь просит открыть лист без фильтров в стандартном состоянии, используй только `options/clearselections` без блоков `select`.

Если пользователь явно просит сохранить текущее состояние или не очищать фильтры, только тогда используй путь с `/state/analysis`.

## Полезная функция Qlik

Текущие фильтры в приложении можно получить функцией:

`=GetCurrentSelections('/select/','/',';')`

Это подтверждает формат:

- префикс выбора: `/select/`
- разделитель между полем и значениями: `/`
- разделитель значений одного поля: `;`

## Рабочий сценарий

1. Определи, что пользователь действительно просит ссылку Qlik.
2. Сначала проверь, что в текущем сообщении пользователя явно есть `Qlik`, `Qlik Sense`, `Клик`, `в клик` или `в qlik`.
3. Если такого упоминания нет, не запускай этот skill и не продолжай сценарий построения ссылки.
4. Найди приложение в разрешённом списке.
5. Если пользователь указал только лист или отчёт без приложения, сначала попробуй найти этот лист по всем разрешённым приложениям.
6. Если лист или отчёт найден только в одном приложении, попроси пользователя подтвердить это приложение.
7. Если лист или отчёт найден в нескольких приложениях, предложи выбрать только из списка этих приложений.
8. Если приложение всё ещё не определено, не угадывай его: сразу предложи выбрать одно из разрешённых приложений из явного списка.
9. Если доступен интерактивный выбор, для приложения используй выбор кнопкой из списка только когда подходящих приложений больше одного.
10. Открой реестр и найди `AppID`.
11. На первом шаге всегда работай только с `mainSheets`.
12. Если пользователь уже указал лист или отчёт, после выбора или подтверждения приложения сразу ищи именно его внутри выбранного приложения и не задавай тот же вопрос повторно.
13. Если лист не указан, предложи выбор листа только внутри выбранного приложения, начиная с `mainSheets`.
14. Если пользователь явно просит технический лист или нужный лист не найден среди `mainSheets`, показывай также `technicalSheets`.
15. Найди лист и его `SheetID`.
16. Если по уже указанному пользователем названию внутри выбранного приложения найден ровно один лист, сразу используй его.
17. Если лист неоднозначен внутри выбранного приложения, попроси уточнение или предложи интерактивный выбор листа.
18. Если фильтры не указаны, не отдавай сразу готовую ссылку: сначала спроси пользователя, нужны ли фильтры.
19. Если пользователь хочет фильтры, попроси его написать поля и значения в свободной форме.
20. Если пользователь явно пишет, что фильтры не нужны, только тогда строй ссылку без фильтров.
21. Если пользователь сам назвал поля, сначала сопоставь их с реестром полей приложения.
22. Перед сборкой ссылки коротко подтверди, какие именно поля ты распознал, и предложи сформировать ссылку.
23. Если пользователь после подтверждения меняет поля или значения, заново проверь все изменённые поля и ещё раз подтверди итоговый набор фильтров.
24. Если пользователь просит помочь подобрать поля или если поля не удалось уверенно распознать, только тогда можно предложить вспомогательные варианты или группы полей.
25. Поддерживай несколько полей в одном запросе и несколько фильтров в итоговой ссылке.
26. Разбери и нормализуй фильтры.
27. По умолчанию используй шаблон с `/options/clearselections`.
28. Если пользователь явно просит сохранить текущее состояние или не очищать фильтры, используй `/state/analysis`.
29. Если поле не найдено в списке полей приложения, предложи похожие поля и вариант подтверждения `такое поле точно существует, отфильтруй по нему`.
30. Если поле не найдено и пользователь не дал явное подтверждение override, не формируй ссылку.
31. Если пользователь явно подтвердил неизвестное поле, разрешай использовать его в ссылке как пользовательское подтверждённое поле.
32. Если формат конкретного фильтра не подтверждён примерами, не придумывай его и запроси у пользователя корректный пример.
33. Собери ссылку на конкретный лист.
34. Выполни базовую проверку:
   - приложение найдено
   - лист найден
   - используются корректные `AppID` и `SheetID`
   - по умолчанию используется `/options/clearselections`
   - `/state/analysis` используется только по явному запросу пользователя
35. Верни только готовый пользовательский результат без описания внутренних шагов проверки.

## Формат ответа

Когда ссылка успешно собрана, отвечай компактно:

- приложение
- лист
- фильтры в человекочитаемом виде
- готовая ссылка в отдельном кодовом блоке без markdown-ссылки, чтобы её было удобно копировать

Если данных недостаточно, не строй предположения там, где есть неоднозначность. Сначала запроси уточнение.

Не показывай пользователю:

- внутренние шаги вроде проверки `AppID`, `SheetID`, реестра и правил skill
- статус вида `OK` или текст о том, что проверка прошла
- служебные предложения о следующих тестовых сценариях, если пользователь сам их не просил
- фразы вроде `Соберу итоговую ссылку`, `Проверю поле`, `Сейчас найду лист`, `Соберу готовую ссылку для выбранного листа`
- фразы вроде `Найду, в каких разрешённых приложениях есть ...`, `дам интерактивный выбор`, `сейчас предложу варианты`

## Ограничения

- Не подменяй приложение на похожее по названию.
- Не выбирай лист по своему усмотрению, если есть несколько подходящих вариантов.
- Не используй этот skill для анализа данных или объяснения выражений.
- Не считай проверку существования поля в приложении полной, если подтверждение есть только по реестру или вспомогательным метаданным.
